# grid fin

Claude Code로 개발할 때 쓰는 개인용 작업 도구입니다. 스킬이 작업 순서를 안내하고, 훅이 지켜야 할 규칙을 강제합니다.

설계 문서와 배포 스크립트가 있습니다. 훅과 검사는 만드는 중입니다.

## 왜 만드나

이전에 쓰던 도구를 실제로 측정해 봤더니 이런 상태였습니다.

| 무엇 | 결과 |
|---|---|
| 훅 9개 | 실제로 작업을 막는 것은 0개 |
| 코드 검토 지적 163건 | 78.5%가 조치되지 않음 |
| 평가 자동화 | 넉 달째 실행되지 않음 |
| 도구 자체의 개선 사항 | 44%가 원본 저장소에 반영되지 않음 |
| 실행 기록 13,342건 | 도구 이름이 전부 `unknown`으로 기록됨 |

전부 같은 문제였습니다. 알려주기만 하고 막지 않았고, 무엇이 일어났는지 나중에 확인할 수 없었습니다.

## 어떻게 다르게 하나

**되돌리기 어려운 것만 막습니다.** 판단이 필요 없고 답이 명확한 조건 일곱 가지만 차단합니다. 예를 들어 커밋 메시지에 이슈 번호가 없으면 커밋이 되지 않습니다.

나머지는 세 가지로 나눕니다. 고칠 수 있으면 고치게 하고, 반복되면 사람에게 넘기고, 진행을 막을 필요가 없으면 알리기만 합니다.

이렇게 나눈 기준은 두 가지입니다. 잘못됐을 때 되돌리는 비용이 얼마나 큰지, 그리고 기계가 명확히 판정할 수 있는지입니다.

## 작업을 네 층으로 나눕니다

| 층 | 무엇 | 어디에 |
|---|---|---|
| 제품 | 무엇을 만드는 서비스인가 | 저장소의 문서 |
| 기능 | 사용자가 체감하는 변화 하나 | GitHub 이슈 |
| 작업 | 커밋 하나로 끝나는 단위 | git 커밋 |
| 학습 | 반복된 실수에서 배운 것 | 규칙과 검사로 승격 |

기능의 진행 상태는 따로 저장하지 않습니다. 커밋과 PR을 조회해서 계산합니다. 기록을 직접 고쳐서 단계를 건너뛸 수 없게 하기 위해서입니다.

## 이름

그리드 핀은 로켓이 착륙할 때 자세를 잡는 격자 모양 날개입니다. 추력을 내지 않고 이미 있는 운동의 방향만 바꿉니다. 평소에는 접혀 있다가 필요할 때만 펴집니다.

이 도구도 같은 역할입니다. 모델의 능력을 늘리지 않고 방향만 잡습니다.

## 만드는 순서

1. 배포 스크립트와 훅을 직접 만듭니다 (배포 스크립트는 끝났습니다)
2. 이 저장소에 설치하고 차단이 실제로 되는지 확인합니다
3. 그다음부터는 이 도구를 써서 나머지를 만듭니다

2번을 지나면 이후의 모든 작업이 검사를 통과해야 합니다. 도구를 만드는 일 자체를 그 도구로 관리하기 위해서입니다.
