## 1. Anthropic의 답 — 압축이 아니라 외부화

장기 실행 에이전트에 대한 공식 지침이 압축의 한계를 먼저 말한다.

> **"compaction isn't sufficient"**

그리고 비유를 든다 — **교대 근무**다.

> **"each new engineer arrives with no memory of what happened on the previous shift"**

답으로 드는 것은 셋이고 **전부 컨텍스트 밖이다**:

1. **외부 상태 파일** — `claude-progress.txt` · `feature_list.json` · **git 이력**
2. **점진적 분해** — 한 번에 한 기능. 전부를 시도하지 않는다
3. **구조화된 인수인계** — 문서를 통해 세션에서 세션으로

> **"The key insight here was finding a way for agents to quickly understand the state of work when starting with a fresh context window."**

**주의 — 이 문서는 에이전트가 자기 컨텍스트 소비를 감시하는 방법을 다루지 않는다.** 임계값도 수치도 없다.

## 2. 임계값에는 합의가 없다

하네스 8종의 소스를 읽고 비교한 자료가 있다. **압축이 언제 터지는가**가 극단적으로 갈린다.

| 하네스 | 임계 | 200K 모델 기준 절대값 |
|---|---|---|
| **Gemini CLI** | **50%** | ~100K |
| Roo Code | 86~92% | 160~184K |
| **Claude Code** | ~89% | ~172K |
| Codex | 90% | ~180K |
| Pi | ~92% | ~184K |
| **opencode** | **96~99%** | 190~198K |

**두 배 차이다.** 같은 문제에 대해 절반에서 터뜨리는 쪽과 마지막까지 버티는 쪽이 공존한다.

**그리고 임계의 단위가 토큰이 아닌 경우가 많다.**

> **"The token-count-based condensers use an event count threshold rather than a token count. No harness-level token counting."**

**참고 하네스의 `suggest-compact.js`가 도구 호출 횟수를 센 것이 이 계열이다** — 예외가 아니라 관행이었다.

**압축에 쓰는 모델도 대개 같은 것이다.**

> **"Every harness except opencode … uses the same model. Compaction is not treated as a task that needs less capability."**

## 3. 누가 압축을 부르는가 — 여기서 갈린다

### 3.1 OpenHands는 에이전트에게 도구를 줬다

OpenHands는 메시지 배열이 아니라 **append-only 이벤트 저장소**를 유지하고, **condenser 아홉 가지**를 꽂아 쓸 수 있게 했다. 그중 하나가 **에이전트가 직접 부르는 것**이다.

에이전트가 `request_condensation` 도구를 호출해 *"컨텍스트가 감당 안 된다"*를 하네스에 알린다. **기본 설정에서는 그것이 압축이 일어나는 유일한 경로다.**

일반적인 압축 방식은 이렇다 — 보이는 이벤트 수가 임계를 넘으면 **앞 몇 개**(시스템 프롬프트와 원래 과제)와 **뒤 몇 개**(최근 작업)를 남기고 **가운데를 요약으로 대체**한다. 요약은 *사용자의 목표 · 에이전트가 이룬 진척 · 남은 일*을 encode하는 데 집중한다.

### 3.2 Claude Code에는 그 도구가 없다 — 실측

**1차 실측(2026-08-09).** 스크래치 프로젝트에서 모델에게 자기 도구 목록을 물었다.

- 즉시 호출 가능한 도구와 지연 로드 도구를 전부 나열했으나 **슬래시 명령을 실행하는 도구는 없다**
- `Skill` 도구는 **스킬만** 부른다. `/compact`·`/clear`는 **CLI 내장이라 어떤 도구로도 실행할 수 없다**

**그리고 훅도 부를 수 없다**(1차, 공식 문서) — 훅은 반응만 하고 되돌려 명령할 통로가 없다. `PreCompact` 훅이 있으나 **종료 코드 2로 막을 수만 있고 일으키지는 못한다.** `manual`/`auto`를 구분하는 matcher가 있다.

> **이 대비가 이 조사의 핵심이다.** OpenHands는 *에이전트가 판단하게* 설계했고, Claude Code는 *하네스가 임계로 판단하게* 설계했다. **후자에서는 하네스가 압축을 유도할 수 없고 사람이 눌러야 한다.**

### 3.3 모델은 스스로 알지 못한다 — 그러나 루브릭이 메운다

`SelfCompact`(프리프린트)가 이 지점을 정면으로 다룬다. 제안은 둘의 조합이다:

> **"(i) a compaction tool the model invokes to summarize the accumulated context, and (ii) a lightweight rubric specifying when to fire (a sub-task has resolved, or the trajectory is converging) and when to suppress (mid-derivation, or when stuck)."**

그리고 **간극을 명시한다**:

> **"although unprompted models cannot reliably tell when their own context is rotting, a lightweight rubric closes this gap"**

**측정된 이득** — 6개 벤치마크 × 7개 모델에서 수학 과제 **최대 +18.1점**, 에이전트 검색 **+5~9점**, **문항당 토큰 비용 30~70% 절감**. 고정 간격 요약과 같거나 그 이상.

**루브릭의 내용이 참고 하네스의 `wf-compact` 표와 같은 방향이다** — *하위 과제가 끝났을 때 압축하고, 도출 중간이거나 막혔을 때는 하지 마라.*

## 4. 압축은 공짜가 아니다

**KV 캐시가 깨진다.**

> **"every time a compaction fires, the cache is busted"**

저자의 계산 — **125,000 토큰 컨텍스트에서 압축 한 번이 $0.40**이고, 이는 **캐시된 요율로 후속 21턴을 도는 것과 같다.** 일찍 압축하는 전략일수록 이 비용을 자주 치른다.

**그리고 요약은 손실이다.**

> **"the more the summary paraphrases rather than quotes, the more the model's understanding of the user's intent can drift"**

**어느 하네스도 이 손실을 다루지 않는다**는 것이 저자의 지적이다.

---

## 5. 길다고 좋은 것이 아니다 — context rot

컨텍스트를 늘려 버티는 전략의 한계가 측정돼 있다.

- 관련 정보가 **앞이나 뒤**에 있으면 정확도가 가장 높고, **중간**으로 가면 **30% 이상** 떨어진다(U자 곡선)
- **6개 모델 계열**(GPT-3.5-Turbo · GPT-4 · Claude 1.3 · LongChat-13B · MPT-30B · Cohere Command)에서 재현됐고 이후 다른 구조에서도 확인됐다
- 구조적 원인으로 **RoPE의 장거리 감쇠**가 지목된다 — 먼 토큰 쌍의 내적 유사도가 낮아져 중간 정보의 어텐션 가중치가 체계적으로 줄고, softmax가 그것을 증폭해 **앞뒤 우위**를 강화한다

**함의** — *"컨텍스트 창이 크니 그냥 채우면 된다"*가 성립하지 않는다. **채우면 가운데가 죽는다.**

## 6. 정리된 갈래 넷 — 그리고 놀라운 일치

Arize가 네 코드베이스(Pi · OpenClaw · Claude Code · Letta)를 읽고 정리한 분류다.

| 층 | 무엇을 다루나 | 수단 |
|---|---|---|
| **파일 컨텍스트** | 파일을 얼마나 읽어 넣나 | 페이지네이션 · 머리/꼬리 절단 · 바이트·토큰 상한 · 중복 제거 |
| **도구 컨텍스트** | 도구 출력이 얼마나 들어오나 | 결과 크기 예산 · **디스크로 내보내고 핸들만 남기기** · 미리보기 |
| **세션 컨텍스트** | 대화가 길어지면 | LLM 요약 · 토큰 임계 · 축출 정책 · 경계 안전 압축 |
| **서브에이전트 컨텍스트** | 위임할 때 | **격리** · 선택적 이력 상속 · 작업 공간 필터 · 메모리를 도구로 |

**측정된 임계값 일부** (자료가 소스에서 뽑은 것):

| 무엇 | 값 | 어디 |
|---|---|---|
| 파일 읽기 상한 | **2,000줄 또는 50KB** | Pi · OpenClaw |
| 파일 읽기 게이트 | 256KB 바이트 · 25K 토큰 예산 | Claude Code |
| 도구 결과 예산 | 16K 문자 **또는 컨텍스트의 30%** | OpenClaw |
| 최근 유지분 | ~20,000 토큰 | Pi |
| 압축 예비분 | 16,384 토큰 | Pi |
| 압축 버퍼 | 13,000 토큰 | Claude Code |
| 압축 트리거 | **컨텍스트의 90%** | Letta |
| 체크포인트 | 50,000 토큰 | Alyx |

그리고 결론이 이렇다:

> **"The most striking finding from comparing these four codebases is not how different they are. It is how much they agree."**

> **"The goal is not to show the model everything. It is to give it the right working set at the right time."**

> **"50 years of computing taught us that the best memory management is the kind the program never thinks about."**

**두 철학으로도 갈린다** — 컨텍스트 증가를 **구조적으로 묶는 쪽**(Prevention: 노드마다 메시지 범위를 제한)과 **자라게 두고 임계에서 압축하는 쪽**(Cure).

## 7. 이 설계에 무엇이 걸리나

**조사 결과이지 결정이 아니다.** 결정은 원장 `Q30`이 받는다.

**ⓐ Anthropic의 답이 이 설계가 이미 한 것과 같은 형태다.** *외부 상태 파일 + 세션 간 인수인계*는 **`story` 상태를 저장하지 않고 산출물에서 계산한다**(원장 S12)와 같은 전략이고, **매체가 git이라는 점까지 겹친다**. 압축에서 살아남는 것 목록(git 상태 · 디스크 파일)과도 맞는다.

**ⓑ 에이전트가 압축을 부르는 길은 이 플랫폼에서 막혀 있다**(관측 4, 1차 실측). OpenHands 방식을 그대로 쓸 수 없다. **남는 것은 「알리고 사람이 누르는 것」이다.**

**ⓒ 그런데 알리는 방법은 이미 확인돼 있다.** 훅은 토큰을 못 받지만(1차 실측) **사용률은 얻을 수 있다.** **⚠ 2026-08-12 정정** — 원래 *“`transcript_path`를 파싱하면 계산된다”*고만 적었다. **상태 표시줄은 계산된 값을 직접 받는다**(관측 14) — 파싱이 필요 없고, **참고 하네스의 파싱 스크립트는 낡았다**(§9). 그리고 **종료 코드 0 + `additionalContext`로 모델에게 도달한다**(원장 S8 실측 6). **참고 하네스가 못 한 부분이 정확히 이 연결이다.**

**ⓓ 막는 것은 가능하다.** `PreCompact` + `auto` matcher + 종료 코드 2로 **위험한 시점의 자동 압축을 차단**할 수 있다(1차 문서, **미검증**). `wf-compact` 표의 *"구현 중간에는 압축하지 마라"*를 **지시가 아니라 기제로** 만들 수 있다 — P7이 요구하는 형태다. **다만 막기만 하면 세션이 죽으므로 유도와 짝이어야 한다.**

**ⓔ 임계값을 지금 정할 근거가 없다.** 관측 2가 보여주듯 **업계 합의가 50%~99%로 갈린다.** 이 저장소가 `Q9`에서 이미 쓴 표현이 그대로 적용된다 — **정해야 하는 것은 값이 아니라 계수기의 존재다.**<br>**⚠ 2026-08-12 정정 — 「값의 근거가 없다」와 「제어할 수 없다」는 다르다.** 이 문장이 후자로 읽혔는데 **틀렸다.** **압축 임계는 세 곳에서 제어할 수 있고 세션마다 다르게 줄 수 있다**(관측 13, §9). **무슨 값이 좋은지가 미정일 뿐이다.**

**ⓕ 압축 비용이 첫 실행의 예산에 들어온다**(관측 5). 압축 한 번이 21턴어치라면 **자주 압축하는 설계는 비싸다.** `D5`가 효과를 재지 않기로 했으므로 **이것은 비용으로만 판단 가능하다.**

## 9. 2026-08-12 보강 — 압축 창은 제어할 수 있다

### 9.1 `/autocompact` — 설정 위치 셋과 우선순위

**압축이 일어나는 임계**를 세 곳에서 정할 수 있다. **우선순위가 있다**(1차, 공식 문서).

| 어디 | 무엇을 하나 | 저장되나 |
|---|---|---|
| **`CLAUDE_CODE_AUTO_COMPACT_WINDOW`** (환경변수) | **가장 세다.** 명령·플래그·설정을 전부 이긴다. 설정돼 있으면 `/autocompact`가 **override 중이라 보고하고 창을 바꾸지 않는다** | — (평문 토큰 수만 받는다) |
| **`--autocompact`** (CLI 플래그) | 그 실행에만 적용. **managed settings 같은 상위 스코프에 선점되지 않는다** | 안 함 |
| **`/autocompact <값>`** (슬래시 명령) | 현재 세션에 적용 + 사용자 설정 `autoCompactWindow`에 저장. **상위 스코프가 그 키를 정했으면 값은 저장되나 세션은 그 스코프의 창을 쓴다**(명령이 그렇게 알려준다) | 함 |

**값의 범위와 형식** — 100K ~ 1M. 평문(`200000`) · 접미사(`500k` · `1M`) · **맨숫자 100~1000은 천 단위**(`200` = 200,000). 환경변수는 **평문만** 받는다. **모델의 컨텍스트 창으로 상한이 걸린다.** `auto`는 모델에 맞춘 기본값.

**뜻** — *압축 전에 컨텍스트 창이 얼마나 찰 수 있는가*. **즉 임계다.**

**1차 실측(2026-08-12)** — 범위를 벗어난 값을 주면 거부하고 사양을 알려준다:

```
$ claude --autocompact 50k
error: option '--autocompact <auto|tokens>' argument '50k' is invalid.
It must be 'auto', or between 100k and 1M (e.g. 500k, 200000, or 200 as shorthand)
```

`--autocompact auto`로 실제 세션이 정상 동작하는 것도 확인했다.

### 9.2 상태 표시줄은 사용률을 계산해서 준다

상태 표시줄 스크립트가 stdin으로 받는 필드에 **이미 계산된 값**이 있다(1차, 공식 문서).

```
context_window.used_percentage         이미 계산된 사용률
context_window.remaining_percentage    남은 비율
context_window.total_input_tokens      입력(캐시 읽기·쓰기 포함)
context_window.total_output_tokens
context_window.context_window_size     200000 기본, 확장 컨텍스트면 1000000
exceeds_200k_tokens                    실제 창 크기와 무관한 고정 임계 플래그
cost.total_cost_usd                    세션 비용 (`/clear` 하면 0으로 리셋)
```

**그래서 참고 하네스의 상태 표시줄 스크립트는 낡았다.** `transcript`를 `tail -200 | jq`로 훑어 `input_tokens + cache_read + cache_creation`을 더하던 것이 **필드 하나로 대체된다.**

**비대칭은 남는다.**

| | 사용률을 받나 | 모델에게 도달하나 |
|---|---|---|
| **상태 표시줄** | **받는다**(계산된 값) | **아니다** — 사람에게 표시만 |
| **훅** | **못 받는다**(1차 실측) | **된다**(종료 코드 0 + `additionalContext`) |

**둘을 잇는 방법은 파일이다** — 상태 표시줄도 셸 스크립트이므로 **받은 사용률을 파일에 적어 두면 훅이나 스킬이 그 파일을 읽는다.** **참고 하네스는 화면에 찍기만 하고 적어 두지 않았다.**

### 9.2.1 상태 표시줄은 훅이 부르지 않는다 — Claude Code가 직접 부른다

**실행 시점**(1차, 공식 문서) — 세션 시작 시 1회(재개 포함), 그 뒤로는 **새 어시스턴트 메시지가 도착할 때** · `/compact`가 끝났을 때 · 권한 모드가 바뀔 때 · vim 모드 토글 · `refreshInterval` 타이머(설정한 경우). **300ms 디바운스**가 걸리고, **실행 중에 새 트리거가 오면 진행 중인 스크립트를 취소한다.**

**그래서 파일에 적어 두는 방법은 충분히 최신이다** — 사실상 매 턴 갱신된다.

**⚠ 다만 함정이 하나 있고 이 설계에 정확히 걸린다.**

> **이벤트 트리거는 메인 세션이 유휴일 때 잠잠해진다** — 예를 들어 코디네이터가 백그라운드 서브에이전트를 기다리는 동안.

**task 세션이나 서브에이전트가 도는 동안 메인의 상태 표시줄이 멈추고, 파일에 적힌 사용률이 그 시간만큼 낡는다.** 문서가 답도 준다 — **`refreshInterval`을 설정해 타이머로도 실행되게 한다.** **세션을 계층으로 나누는 구조를 검토 중이므로 이 설정이 필요조건이 된다.**

**참고 하네스가 두 값을 다르게 얻는 것도 확인했다**(1차, 스크립트 직접 읽음) — **현재 토픽**은 `dev-context.js read`로 **파일에서 읽고**(그 파일은 훅과 명령이 갱신한다), **컨텍스트 사용량**은 transcript를 파싱해 **스스로 계산한다.**

### 9.3 그 밖에 확인된 것 넷

- **`/clear`는 비용이 0이고 `/compact`는 큰 요청이다** — *"compacting a large context is itself a large request"* ⇄ *"When you want a fresh start instead of continuity, `/clear` costs nothing"*. **새 세션을 띄우는 쪽이 압축보다 싸다는 근거**가 된다
- **서브에이전트 위임이 공식 권장이다** — *"verbose output stays in the subagent's context while only a summary returns to your main conversation"*
- **`CLAUDE.md`는 200줄 이하 권장** — 특정 워크플로우용 지시는 **스킬로 옮기라**고 한다. 스킬은 호출될 때만 로드되기 때문이다. **원장 `Q31`(스킬 로딩)에 직접 걸린다**
- **훅을 컨텍스트 관리 수단으로 쓸 수 있다** — 10,000줄 로그를 훅이 걸러 수백 토큰으로 줄이는 예가 공식 문서에 있다. **이 조사가 안 본 각도였다**
- **에이전트 팀은 토큰을 약 7배 쓴다** — 팀원마다 자기 컨텍스트 창을 갖기 때문이다. **기본으로 꺼져 있다**

### 9.4 이 설계에 주는 것

**압축 임계를 세션 종류마다 다르게 줄 수 있다.** 3계층 세션 구조(메인 → 워크트리 → task)를 검토 중인데, **워크트리 세션은 길게 살고 task 세션은 커밋 하나로 끝난다** — 같은 창을 쓸 이유가 없다. 배치 스크립트가 **호출마다 `--autocompact`를 지정**하거나 **환경변수로 일괄** 정할 수 있다.

**다만 무슨 값이 좋은지는 여전히 미정이다**(관측 2). 제어 수단이 있다는 것과 값의 근거가 있다는 것은 다르다.

## 8. 이 조사가 재지 않은 것

- **`PreCompact` 종료 코드 2가 실제로 자동 압축을 막는지 실측하지 않았다.** 공식 문서 서술이고, **이 저장소는 같은 문서에서 다른 서술이 틀린 것을 한 번 잡았다**([repository-layout §10.2 정정](repository-layout.md)). **미검증으로 안고 간다.**
- **하네스 8종의 임계값을 직접 소스에서 확인하지 않았다.** 소스를 읽은 2차 자료의 표를 인용했다. **Claude Code의 ~89%조차 그 자료의 값이고 이 저장소가 재지 않았다.**
- **압축 비용 $0.40은 저자의 계산**이고 조건(모델·요율·캐시 상태)이 명시되지 않았다. **자릿수의 감으로만 쓴다.**
- **context rot의 30% 하락은 2023년 논문 값**이다. 이후 모델에 같은 폭이 적용되는지는 확인하지 않았다 — **U자 곡선의 존재는 재현됐으나 크기는 모델마다 다를 수 있다.**
- **`SelfCompact`의 이득은 벤치마크 값**이고 **코딩 에이전트 과제가 아니다**(수학 · 에이전트 검색). 이 설계로의 전이는 미검증이다.
- **Aider · Cline의 방식을 찾지 못했다.** 검색이 OpenHands 자료로 수렴했다.
- **`/autocompact`가 실제로 그 임계에서 압축을 일으키는지 재지 않았다.** 인자 검증과 정상 실행만 확인했고, **창을 작게 준 세션이 실제로 그 지점에서 압축하는지는 관측하지 않았다.**
- **상태 표시줄 필드는 공식 문서 서술이고 실측하지 않았다.** 이 저장소는 같은 문서에서 다른 서술이 틀린 것을 한 번 잡았다([repository-layout §10.2 정정](repository-layout.md)).
- **서브에이전트 격리가 컨텍스트를 실제로 얼마나 아끼는지** 측정된 값을 찾지 못했다. 이 설계는 검토 주체를 서브에이전트로 두기로 했으므로(원장 S20) **그 이득이 관측 대상이다.**
