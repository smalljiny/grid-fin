# 훅 스크립트 4개 — 작업 스펙

## 1. 개요

### 1.1 배경

**이슈 #1이 배포 경로를 만들었고, 훅 스크립트는 자리표시본으로 들어갔다.** 지금 `payload/`의 상태가 설계와 세 곳에서 어긋나 있다(1차, 직접 확인 2026-08-20).

| 어긋난 곳 | 지금 상태 | 설계 |
|---|---|---|
| 쓰기 경계 | **`PreToolUse`의 `Write` matcher가 `pre-commit.py`를 가리킨다.** 배선이 뒤바뀌어 있다 | 쓰기 경계와 커밋 경계는 다른 스크립트다([판정 문서 §5-2](../../draft/judgment.html#5-2)) |
| 스크립트 수 | 파일이 3개다. 쓰기 경계 스크립트가 없다 | 4개([저장 문서 §7-4](../../draft/storage.html#7-4)) |
| 포맷 훅 | `format.py`가 어디에도 등록돼 있지 않고, `payload/rules.json`에 `PostToolUse` 소유 지점이 없다 | 사건 3개에 훅 4개 |

**그리고 워크트리에는 게이트가 없다.** 배포물을 git으로 추적하지 않기로 했으므로(미결 목록 파일의 S26 — 대상 저장소가 내 것만이 아니면 개인용 하네스를 커밋할 수 없다), 커밋이 워크트리를 덮어 주지 않는다. **워크트리를 만든 뒤 하네스를 넣는 주체가 있어야 한다.** 그 주체가 없으면 [흐름 문서](../../draft/flow.html)의 ③ 착수가 요구하는 배포물 확인이 대조할 대상 자체를 갖지 못한다.

### 1.2 목적

**게이트를 실제로 강제하는 실행물을 만든다.** 배포는 파일을 옮길 뿐이고, 무엇을 막을지는 훅이 정한다. 그리고 **워크트리에서도 같은 게이트가 살아 있게 한다.**

## 2. 목표

무엇이 참이 되면 이 이슈가 끝나는가.

1. **훅 4개가 사건 3개에 등록되고, 선언과 스크립트 파일이 서로 짝이 맞는다.**
2. **차단해야 하는 두 경계가 실제로 멈춘다** — 메시지를 내는 것이 아니라 도구 호출이 진행되지 않는다.
3. **차단하지 못하는 지점에서는 차단한다고 주장하지 않는다.** 도달이 확인된 채널로 알리고, 실제 차단은 차단이 성립하는 경계로 옮긴다.
4. **워크트리에 하네스를 넣고, 넣은 항목이 `git status`에 뜨지 않는다.**
5. **재배포가 옛 훅 선언을 지우고 새 선언을 넣는다** — 지금 배선이 뒤바뀐 상태가 갱신으로 고쳐진다.

## 3. 구조

### 3.1 사건 3개 · 스크립트 4개

| 사건 | matcher | 스크립트 | 하는 일 | 차단 |
|---|---|---|---|---|
| `SessionStart` | 없음 | `session-start.py` | 훅 등록 확인 · 매니페스트 확인 | **차단하지 못한다**(§3.3) |
| `PreToolUse` | `Write\|Edit` | `pre-write.py` | 쓰기 경계 — 파일 경계 | 종료 코드 2 |
| `PreToolUse` | `Bash` | `pre-commit.py` | 커밋 경계 — 커밋 명령 인식 | 종료 코드 2 |
| `PostToolUse` | `Write\|Edit` | `format.py` | 포맷 사후 교정 | 차단하지 않는다 |

**사건이 3개인 것은 [흐름 문서](../../draft/flow.html)가 정한 값이고, 스크립트가 4개인 것은 [저장 문서 §7-4](../../draft/storage.html#7-4)의 배포 단위 표에 있다.**

**`pre-commit.py`의 이름은 자리표시본에서 그대로 가져온다.** git의 `pre-commit` 훅과 이름이 겹치지만 다른 것이다. 이것은 Claude Code의 `PreToolUse` 훅이고, `Bash` 도구 호출의 명령 문자열을 본다.

### 3.2 훅의 공통 계약

**입력은 stdin의 JSON 1개다.** 실측으로 확인한 필드는 `session_id` · `transcript_path` · `cwd` · `hook_event_name`이고, `SessionStart`는 `source`를 함께 준다(1차 실측 2026-08-20, Claude Code 2.1.237). `PreToolUse`는 `tool_input`에 `file_path`와 `content` 전문을 준다([훅 실측 조사](../../research/hook-skill-frontmatter-probe.md) M2, 1차 실측 2026-08-09).

**출력 채널은 3개이고 성질이 다르다.**

| 채널 | 도달하나 | 어디에 쓰나 |
|---|---|---|
| 종료 코드 2 + stderr | `PreToolUse`에서 도달한다. 도구 호출이 진행되지 않는다 | 차단하는 두 경계 |
| 종료 코드 0 + stdout JSON의 `hookSpecificOutput.additionalContext` | 도달한다 | 알리기만 하는 두 훅 |
| 종료 코드 0 + stderr | **도달하지 않는다** | 쓰지 않는다 |

**셋째 줄이 이 설계가 가장 경계하는 형태다.** 참고 하네스가 경고를 냈는데 모델에게 닿지 않았고, 그 결과 지적이 「안 고침」인지 「안 들림」인지 구별되지 않았다([강제 기제 조사](../../research/enforcement-mechanisms.md), 지적 163건 중 78.5% 미조치).

**보고는 기계가 읽을 수 있는 형태로 낸다.** 「사람이 읽는 출력을 계약으로 쓰지 않는다」는 이슈 #1의 규칙이 여기에도 걸린다. 문구를 다듬을 때마다 검증이 깨지면 안 된다.

**형식은 고정 토큰 1개 + JSON 1줄이다.** 사람이 읽는 문장은 그 앞뒤에 자유롭게 둔다.

```
GRIDFIN_GATE {"ok":false,"missing":[{"kind":"hook_declaration","path":".claude/scripts/hooks/format.py"}]}
```

| 무엇 | 값 |
|---|---|
| 토큰 | 게이트 판정은 `GRIDFIN_GATE`, 포맷 보고는 `GRIDFIN_FORMAT` |
| `ok` | 참·거짓 |
| `missing[].kind` | **이 이슈가 내는 값 8개**(아래 표). **목록은 닫혀 있지 않다** — 이슈 #3이 선언된 검사 도구의 미설치를 `tool_missing`으로 더한다. **읽는 쪽은 모르는 `kind`를 만나도 결손으로 센다** |
| `missing[].path` | 대상 저장소 루트 기준의 상대 경로 |
| `changed` | `GRIDFIN_FORMAT`에서 고쳐 쓴 파일의 경로 목록 |

**`kind` 8개.** 처음에는 3개로 적었는데 **구현하며 늘었다**(T2, 2026-08-20).

| `kind` | 뜻 | 복구 |
|---|---|---|
| `manifest` | 매니페스트가 없다 | 재배포 |
| `manifest_unreadable` | 매니페스트를 읽을 수 없다 | 고친다 |
| `settings` | 설정 파일이 없다 | 재배포 |
| `settings_unreadable` | 설정 파일을 읽을 수 없다 | 고친다 |
| `hook_declaration` | 매니페스트에 있는데 선언에 없다 | 재배포 |
| `hook_file` | 선언이 가리키는 파일이 없다 | 재배포 |
| `project_root` | 루트를 알아낼 수 없다 | 루트에서 세션을 연다 |
| `hook_error` | 훅이 예상 밖 예외로 끝났다 | 원인을 본다 |

**없는 것과 읽을 수 없는 것을 가르는 이유는 복구가 다르기 때문이다.** 없으면 재배포가 답이고, 깨졌으면 고치는 것이 답이다. **하나로 묶으면 부르는 쪽이 무엇을 할지 정할 수 없다.**

**`hook_error`가 있는 이유.** 「어느 경우에도 종료 코드 2를 내지 않는다」는 **열거로 보장되지 않는다.** 바깥에서 모든 예외를 잡아 0으로 끝내는 경로를 하나로 두되, **조용히 지나가지 않게** 예외를 결손으로 싣는다. 삼키면 결손이 있는데 통과한 것으로 보인다.

**같은 형식을 세 곳이 함께 쓴다.** 세션 시작은 `additionalContext`에, 차단하는 두 훅은 stderr에, 포맷 훅은 `additionalContext`에 싣는다. **판정하는 곳이 셋인데 형식이 하나이므로 시험이 하나의 파서로 셋을 다 읽는다.**

**훅은 배포된 트리에 파일을 만들지 않는다.** 공용 모듈을 가져다 쓰면 Python이 `__pycache__`를 만드는데, **매니페스트에 없는 파일이 배포물 옆에 쌓이면 배포물 확인이 대조할 대상과 실제가 갈린다.** 그리고 그것이 `payload/`로 새어 들어가면 **이진 파일이라 3-way merge가 실패해 배포가 통째로 거부된다**(1차 실측 2026-08-20 — 이슈 #1의 시험 31개가 그것으로 깨졌다). 공용 모듈을 가져오기 전에 바이트코드 쓰기를 끈다.

**예외가 나면 차단 훅은 막고 비차단 훅은 통과시킨다.** stdin이 JSON이 아니거나 스크립트가 예외로 끝나는 경우다. 차단 훅이 예외에서 통과하면 검사하지 않은 것이 통과한 것으로 보이고, 그것이 fail-open이다.

### 3.3 SessionStart는 차단하지 못한다 — 실측

**이 저장소는 `SessionStart`의 종료 코드 2를 잰 적이 없었다.** [판정 문서 §5-2](../../draft/judgment.html#5-2)의 훅 실측 6개는 `PreToolUse`와 `PostToolUse`만 다룬다. 이 스펙을 쓰면서 직접 쟀다.

**측정 환경**: Claude Code 2.1.237 · darwin 25.5.0 · 스크래치 프로젝트 · `claude -p --output-format json`. 사용자 저장소의 `.claude/`는 건드리지 않았다.

| # | 잰 것 | 결과 | 무엇을 정하나 |
|---|---|---|---|
| **M-A** | `SessionStart` 종료 코드 2 | **세션이 그대로 진행됐다.** `is_error: false` · 종료 코드 0 · 모델이 답을 냈다. **훅은 발화했다** — 부수 효과 파일과 stdin JSON이 남았다. **stderr의 표식 문자열은 모델에게 도달하지 않았다** | **세션 시작에서 차단이 성립하지 않는다** |
| **M-B** | `SessionStart` 종료 코드 0 + stdout JSON의 `hookSpecificOutput.additionalContext` | **도달했다.** 모델이 표식 문자열을 그대로 회수했다 | 알리는 채널은 성립한다 |

**근거 등급: 1차 실측**(2026-08-20, 이 세션에서 직접 실행).

**그래서 구조가 갈린다.** [흐름 문서](../../draft/flow.html)는 ② 세션 시작에 하드 차단 하나를 두었는데, 훅 하나로는 그것을 강제할 수 없다. **차단을 차단이 성립하는 경계로 옮긴다.**

```
SessionStart  →  등록을 확인한다  →  결손이면 additionalContext로 알린다 (막지 않는다)
PreToolUse    →  같은 확인을 다시 수행한다  →  결손이면 종료 코드 2로 막는다
```

**기대 목록은 매니페스트에서 나온다.** 「배포물이 있다」와 「훅 4개가 등록됐다」는 다른 계약이고, 매니페스트의 `files`는 앞엣것까지만 답한다(미결 목록 파일의 S27). **교차 검사가 확인이다.**

1. 매니페스트의 `files`에서 **`.claude/scripts/hooks/`의 직속 자녀**를 뽑는다. 이것이 기대 목록이고, **저장소 루트 기준의 상대 경로**다.
2. `.claude/settings.json`의 훅 선언을 파싱해 명령 경로의 집합을 만든다.
3. **양쪽을 같은 형태로 맞춘 뒤에 비교한다**(아래).
4. 기대 목록이 그 집합에 전부 들어 있는지 본다.
5. 선언된 경로가 파일로 존재하는지 본다.

**정규화 규칙이 있어야 3번이 성립한다.** 두 값의 형태가 다르다 — 매니페스트는 `.claude/scripts/hooks/format.py`이고 선언은 `${CLAUDE_PROJECT_DIR}/.claude/scripts/hooks/format.py`다. **맞추지 않고 비교하면 교집합이 비어 모든 훅이 빠진 것으로 판정된다**(1차 실측 2026-08-20, 스텁으로 확인).

| 선언의 형태 | 어떻게 맞추나 |
|---|---|
| `${CLAUDE_PROJECT_DIR}/<상대 경로>` · `$CLAUDE_PROJECT_DIR/<상대 경로>` | 접두를 벗긴다 |
| 프로젝트 루트 아래의 절대 경로 | 루트를 기준으로 상대 경로를 만든다 |
| 그 밖 | **기대 목록과 대조하지 않는다.** 사용자가 더한 훅이므로 하네스의 관심 밖이다 |

**명령 문자열의 첫 낱말을 경로로 본다.** 하네스가 배포하는 선언은 셔뱅으로 부르므로 경로가 언제나 첫 낱말이고, 뒤에 인자가 붙어도 첫 낱말은 그대로다. **`bash <경로>`처럼 다른 프로그램이 앞에 오는 형태는 기대 목록과 맞지 않게 되고, 그러면 위 표의 셋째 줄에 따라 사용자가 더한 훅으로 취급한다.** 하네스가 그런 형태를 쓰지 않으므로 손실이 없다.

**프로젝트 루트는 stdin JSON의 `cwd`에서 얻는다.** 훅 실측 조사가 루트에서 세션을 시작하면 `cwd`와 `CLAUDE_PROJECT_DIR`가 모두 루트를 가리키는 것을 쟀다(M3, 1차 실측 2026-08-09). **환경변수를 먼저 보고 없으면 `cwd`를 쓴다** — 둘 다 없으면 판정할 수 없으므로 차단 훅은 막는다.

**그래서 규칙이 하나 따라온다 — 등록되지 않는 파일을 `.claude/scripts/hooks/`에 두지 않는다.** 기대 목록이 그 디렉터리에서 나오므로, **등록되지 않는 파일을 거기 두면 확인하는 코드가 자기 자신을 결손으로 잡는다.**

**훅이 함께 쓰는 코드는 `.claude/scripts/gridfin/`에 둔다.** 파일 하나이고 이름은 `gate.py`다. 등록 확인·경로 정규화·프로젝트 루트 판정·보고 형식을 담고, 훅 3개가 가져다 쓴다(`session-start.py` · `pre-write.py` · `pre-commit.py`). **`format.py`는 쓰지 않는다** — 차단하지 않으므로 등록 확인을 부르지 않는다.

**「직속 자녀」로 못 박는 이유는 나중에 하위 디렉터리를 만들 때 같은 자기모순이 되살아나기 때문이다.** `hooks/lib/`를 만드는 순간 그 안의 파일이 기대 목록에 들어간다.

**등록 4개는 그대로다.** [저장 문서 §7-4](../../draft/storage.html#7-4)가 **「등록 4개는 훅만 센다」**고 이미 적어 두었다. 공용 모듈은 훅이 아니므로 세지 않는다. **다만 배포 단위 표에는 보여야 한다** — 표에 없는 것을 배포하면 이슈 #1이 겪은 「목록이 없어서 빠진 것이 안 보였다」와 같은 상태가 된다.

**`payload/rules.json`에는 더하지 않는다.** `bin/gridfin`은 규칙을 못 찾으면 텍스트 3-way merge로 떨어지고, `gate.py`는 텍스트 파일이므로 그것이 맞는 처리다. **소유 지점을 더하면 필요 없는 계약이 하나 늘고 유일성 검사 대상도 는다.**

**기대 목록을 스크립트 안에 적지 않는다.** 훅이 늘거나 줄면 매니페스트가 따라 바뀌므로 고칠 곳이 늘지 않는다. 배포 대상이 늘어도 배포 스크립트를 고치지 않는다는 이슈 #1의 계약과 같은 형태다.

**매니페스트가 없으면 차단한다.** 훅이 실행되고 있다는 것 자체가 배포됐다는 증거이므로, 그 상태에서 기록만 사라진 것은 정상이 아니다. 통과시키면 **기록을 지우는 것으로 게이트를 지날 수 있다.** 복구 경로는 재배포이지 설정 직접 편집이 아니다.

**확인 결과를 파일로 남기지 않는다.** 상태를 저장하지 않고 산출물에서 계산한다는 원칙(미결 목록 파일의 S12 — 상태를 별도로 저장하면 저장된 값과 실제가 갈린다)이 여기에도 적용된다. `settings.json`을 읽어 판정하는 비용은 훅 호출 1회당 파일 1개 파싱이다.

**눈먼 지점 하나를 명시한다.** 훅 등록이 **통째로** 사라지면 확인할 주체도 함께 사라져 아무것도 잡지 못한다. 잡히는 것은 **일부만 사라진 경우**다. §6의 「이 검증이 재지 않는 것」에 남긴다.

### 3.4 쓰기 경계 — 파일 경계 하나만 본다

[판정 문서 §5-2](../../draft/judgment.html#5-2)는 쓰기 경계에 파일 경계 · 금지 패턴 · 시크릿 3개를 두었다. **이 이슈는 파일 경계만 만든다.**

**가르는 기준은 오탐이다.** 차단하는 계층은 오탐 0%를 요구한다. 파일 경계는 경로 비교라 오탐이 원리적으로 없다. 금지 패턴과 시크릿은 규칙 목록이 있어야 하고, 그 목록은 선언 설정 파일이 담는다(이슈 #3). §5로 보낸다.

**판정**: `tool_input.file_path`를 절대 경로로 푼 뒤 프로젝트 루트 아래인지 본다. 밖이면 종료 코드 2다.

**심볼릭 링크를 따라간 뒤 비교한다.** 루트 안의 심볼릭 링크가 밖을 가리키면 경로 문자열만으로는 안에 있는 것으로 보인다.

### 3.5 커밋 경계 — 인식과 fail-closed까지

`Bash` 도구 호출의 `tool_input.command`를 읽어 **커밋 명령인지** 판정한다.

**인식이 뚫려야 하는 형태 4개**: 인용(`git "commit"`) · 환경변수 접두(`GIT_AUTHOR_NAME=x git commit`) · 복합 명령(`git add . && git commit -m ...`) · 경로 지정(`git -C sub commit`).

**커밋 명령이면 선언 설정 파일을 찾는다.** 경로는 **대상 저장소 루트의 `gridfin.json`** 이다. 위치는 이미 정해져 있었고(미결 목록 파일의 D4 — 루트에 선언 설정 파일 1개를 둔다), **이 스펙이 정하는 것은 이름뿐이다.** 형식과 내용은 이슈 #3이 정한다.

| 상태 | 판정 | 종료 코드 |
|---|---|---|
| 선언 설정 파일이 없다 | **결손** | 2 |
| 선언 설정 파일이 있다 | 통과 | 0 |
| 커밋 명령이 아니다 | 통과 | 0 |

**둘째 줄이 이 이슈에서 통과인 이유를 밝힌다.** 검사를 실제로 실행하고 결과 객체를 기대값과 대조하는 것은 어댑터의 일이고(이슈 #4), 무엇을 실행할지 선언하는 것은 선언 설정 파일의 일이다(이슈 #3). **이 이슈가 확정하는 것은 경계 인식과 부재 처리다.**

**부재를 통과가 아니라 차단으로 두는 것이 이 표의 요점이다.** 선언되지 않은 부재를 결손으로 잡는다는 규칙이 여기서 처음 실행물이 된다. 이 규칙이 없으면 검사가 없는 것과 검사가 통과한 것이 같은 값으로 보인다.

**정상 경로를 막지 않는다.** 선언 설정 파일은 이슈 #3이 배포 대상에 넣고, grid fin 저장소에 배포하는 시점은 M0 네 가지가 모두 끝난 뒤인 CP1이다. **이 이슈의 시험은 선언 설정 파일을 픽스처로 만들어 넣는다** — 이슈 #3의 산출물에 의존하지 않는다.

### 3.6 포맷 훅 — 차단하지 않고 알린다

`PostToolUse`에서 실행되고 파일은 이미 쓰인 뒤다. **고칠 수 있는 것을 막으면 왕복만 쓴다**([판정 문서 §5-2](../../draft/judgment.html#5-2)).

**바꿔 쓴 사실을 반드시 알린다.** 훅이 쓰기 전에 내용을 바꾸는 것은 되지만 조용하다 — 실측에서 디스크는 바뀐 내용이었고 모델은 자기가 쓴 내용을 그대로 알고 있었다([판정 문서 §5-2](../../draft/judgment.html#5-2) 실측 5). **그래서 포맷은 쓴 뒤에 고치고, 고친 사실을 `additionalContext`로 보낸다**(실측 6).

**「알리기만 하는 훅은 만들지 않는다」와 충돌하지 않는다.** 그 규칙이 가리키는 것은 **도달하지 않는 채널**(종료 코드 0 + stderr)이다. `additionalContext`는 도달이 확인된 채널이므로 알린 것이 실제로 알린 것이 된다.

**이 이슈가 만드는 것은 채널과 보고 형식이고, 도구 호출의 최소 계약을 함께 정한다.** 어느 언어에 어느 포맷 도구를 쓰는지는 선언 설정 파일이 담는다(이슈 #3).

| 상태 | `format.py`가 하는 일 |
|---|---|
| 선언 설정 파일이 없다 | 아무것도 하지 않고 종료 코드 0으로 끝난다. stdout에 아무것도 쓰지 않는다 |
| 선언 설정 파일이 있고 그 파일에 포맷 도구 선언이 없다 | 위와 같다 |
| 선언 설정 파일에 포맷 도구 선언이 있다 | 선언된 명령을 부르고, 파일이 바뀌었으면 `GRIDFIN_FORMAT`으로 보고한다 |

**셋째 줄을 판정하려면 「무엇을 선언으로 읽는가」가 있어야 한다.** 선언 설정 파일의 이름을 정한 것과 같은 이유다 — **읽는 지점을 모르면 구현할 수도 시험할 수도 없고, 두 이슈가 서로를 기다린다.**

**이 이슈가 읽는 지점은 하나다.** `gridfin.json`의 `format` 아래, 파일 확장자를 키로 하는 명령 배열이다.

```json
{ "format": { ".py": ["ruff", "format"] } }
```

| 규칙 | 값 |
|---|---|
| 키 | `tool_input.file_path`의 확장자. 점을 포함한다 |
| 값 | 명령과 인자의 문자열 배열. **대상 파일 경로를 마지막 인자로 덧붙여 부른다** |
| 확장자가 키에 없다 | 아무것도 하지 않는다 |
| `format` 절이 없다 | 아무것도 하지 않는다 |

**이 이슈가 정하는 것은 이 지점 하나이고, `gridfin.json`의 나머지 절은 전부 이슈 #3이 정한다.** 시험은 이 형태로 **선언 설정 파일을 픽스처로 만들어** 가짜 포맷 명령을 선언한다. 이슈 #3의 산출물에 의존하지 않는다.

**대가를 적어 둔다.** 이슈 #3이 이 지점의 형태를 바꾸기로 하면 `format.py`도 함께 고쳐야 한다. **바꿀 근거가 생기면 바꾸는 것이 맞고, 그때 고칠 곳이 한 함수라는 것을 지금 적어 둔다.**

**커밋 경계와 다른 점을 밝혀 둔다.** 커밋 경계는 선언 설정 파일의 부재를 **결손으로 보고 차단**하는데, 포맷은 **통과시킨다.** 포맷은 차단하지 않는 계층이므로 부재를 결손으로 셀 근거가 없다. 결손은 진행을 판정하는 게이트의 개념이다.

### 3.7 워크트리 주입 스크립트

**배포물이 아니라 하네스 도구다.** [저장 문서 §7-4](../../draft/storage.html#7-4)의 배포 단위 8가지에 주입 스크립트가 없다. 대상 프로젝트에 설치되는 것이 아니라 하네스 저장소에서 실행된다. **`bin/gridfin-inject`로 두고 `bin/gridfin`을 고치지 않는다** — 배포 대상이 늘어도 배포 스크립트를 고치지 않는다는 이슈 #1의 계약을 지킨다.

**입력**: 워크트리 경로 1개. **읽는 것**: 메인 저장소의 매니페스트.

**넣는 것은 매니페스트의 `files` + 매니페스트 자신이다.** `files`에는 훅 스크립트 4개와 공용 모듈, `settings.json`, 선언 설정 파일이 전부 들어 있으므로 **목록을 순회하면 공용 모듈도 함께 간다.** `files`는 자기 자신을 담지 않는다 — 자기 해시를 자기 안에 담을 수 없기 때문이다(미결 목록 파일의 S27). **그래서 매니페스트는 목록을 순회해 나오는 것이 아니라 규칙으로 하나 더 넣는다.** 넣지 않으면 워크트리의 훅이 기대 목록을 만들지 못해 §3.3의 등록 확인이 매번 결손으로 떨어진다.

**넣는 방법은 복사 하나다.** 디렉터리 심볼릭 링크를 만들지 않는다 — 워크트리의 `.claude`가 메인을 가리킬 때 **메인의 훅이 바뀌는 것이 관측됐다**(미결 목록 파일의 S27, 1차 실측 2026-08-19). 복사하면 워크트리에서 고친 것이 워크트리와 함께 사라진다. 가장 좁은 층을 기본으로 둔다는 원칙([저장 문서](../../draft/storage.html))과 같은 방향이다.

**대가를 적어 둔다.** 메인의 하네스를 갱신해도 살아 있는 워크트리는 옛 버전을 쓴다. 매니페스트를 함께 복사하므로 리비전 차이는 보인다.

**무시 목록 등록에 실측 제약 3개가 걸린다**(전부 미결 목록 파일의 S27, 1차 실측 2026-08-19).

| 제약 | 결과 |
|---|---|
| 워크트리의 `.git`은 디렉터리가 아니라 파일이다 | `test -d .git`으로 판정하지 않는다 |
| `.git/info/exclude`를 문자 그대로 쓰면 워크트리에서 실패한다 | `git rev-parse --git-common-dir`로 푼다 |
| 워크트리 전용 exclude를 git이 읽지 않는다 | 블록은 저장소당 1개다. 메인과 모든 워크트리에 함께 걸린다 |

**⚠ 2026-08-20 정정 — 주입은 무시 목록을 쓰지 않는다. 확인만 한다.** 이 절은 원래 주입이 등록한다고 적었다. **실측이 반증했다**(1차 실측 2026-08-20, 이 세션에서 직접 실행).

**배포가 심은 블록이 워크트리를 이미 덮는다.** 배포된 저장소에서 워크트리를 만들고 배포물을 복사한 뒤 `git status --porcelain`을 재니 **비어 있었다.** 블록이 저장소 공용 `.git/info/exclude`에 있고 패턴이 `/.claude/` · `/.harness/`로 앵커돼 있기 때문이다.

**그래서 쓰는 주체를 둘로 만들지 않는다.** 배포와 주입이 같은 블록을 각각 쓰면 어느 쪽이 옳은지 겨루게 되고, 그것이 참고 하네스에서 관리 블록이 통짜 무시에 덮인 형태와 같은 뿌리다. **주입은 결과를 확인하고, 덮이지 않으면 보고한 뒤 부분 실패로 끝낸다.** 고치는 방법은 메인에서 재배포하는 것이다.

**S26의 서술 하나가 여기서 닫힌다.** S26은 「주입한 항목만 등록한다」고 적었는데 **등록 단위가 저장소라 워크트리 단위로는 성립하지 않았다.** 이제 주입이 등록하지 않으므로 그 문장이 가리킬 동작 자체가 없어졌다.

**앵커는 배포가 붙인다.** 이 저장소의 `.gitignore` 3번째 줄 `.claude/`에 앵커가 없어 하위 경로의 같은 이름까지 잡는 것이 이슈 #1에서 나왔다(1차 실측 2026-08-19). 배포가 `/.claude/`처럼 앞에 `/`를 붙여 루트 기준으로 고정하고, **주입은 그것이 실제로 그렇게 동작하는지 확인한다.**

**워크트리인지 가르는 방법도 실측으로 정했다.** `git rev-parse --git-dir`와 `--git-common-dir`가 **다르면 워크트리이고 같으면 메인이다**(1차 실측 2026-08-20). `test -d .git`으로 판정하지 않는 이유가 이것이다 — 워크트리의 `.git`은 파일이다.

**이미 추적되는 항목은 건너뛴다.** 추적되는 파일을 exclude에 넣어도 git은 무시하지 않고, 덮어쓰면 사용자의 커밋된 파일이 바뀐다.

### 3.8 갱신 경로 — 배선이 뒤바뀐 상태가 고쳐진다

`payload/rules.json`이 `PostToolUse`를 소유 지점으로 등록하지 않고 있다. **등록하지 않으면 포맷 훅 선언이 3-way merge를 타지 못한다.** 소유 지점을 늘린다.

**소유 지점을 늘리면서 나머지 3개가 그대로인지 함께 본다.** `permissions.allow`는 이 이슈가 고치지 않지만, **`rules.json`을 고치는 김에 깨질 수 있는 것이 그것뿐이다.** 소유 지점이 빠지면 재배포가 사용자의 허용 목록을 덮거나 하네스의 갱신을 놓친다. **고친 곳만 보면 고치다 깬 곳을 못 본다.**

**`rules.json`은 데이터이지 배포 스크립트가 아니다.** 이슈 #1의 「배포 대상이 늘어도 배포 스크립트는 고치지 않는다」와 충돌하지 않는다.

**식별자 유일성을 확인한다.** 소유 지점의 원소 식별자는 `(matcher, command)` 쌍이다(미결 목록 파일의 S27, 1차 실측 — 어느 한 필드도 단독으로는 유일하지 않다). 새 배선에서 `PreToolUse`가 원소 2개가 되므로 쌍이 유일한지 확인해야 한다.

**갱신이 지나야 하는 경로 하나가 이 이슈에서 처음 실행된다.** 지금 설치본의 `PreToolUse`는 `(Write, pre-commit.py)` 1개이고, 새 배포본은 `(Write|Edit, pre-write.py)`와 `(Bash, pre-commit.py)` 2개다. **식별자가 바뀌었으므로 삭제 1개와 추가 2개로 갈린다.** 옛 항목이 남으면 뒤바뀐 배선이 살아남는다.

### 3.9 실패 범위와 종료 코드

**훅**은 Claude Code의 규약을 따른다. 0은 통과, 2는 차단이다.

**주입 스크립트**는 `bin/gridfin`과 같은 계약을 쓴다. 0은 완전 성공, 1은 부분 실패, 2는 전체 거부다. **전체 거부**는 입력이 잘못됐다는 신호이므로 아무것도 쓰지 않는다 — 대상이 워크트리가 아님 · 매니페스트 부재 · 대상이 메인 저장소 자신. **부분 실패**는 나머지를 진행하고 마지막에 0이 아닌 값을 낸다 — 항목 하나를 복사하지 못한 경우다.

**사람이 읽는 출력을 계약으로 쓰지 않는다.** 문구를 다듬을 때마다 검증이 깨진다.

## 4. 의사결정

| 항목 | 결정 | 근거 |
|---|---|---|

## 6. 검증 조건

무엇이 참이어야 하는가만 적는다. 실행본은 구현 단계의 산출물이다.

**조건이 두 층이다. 섞지 않는다.**

| 층 | 무엇을 부르나 | 무엇을 판정하나 |
|---|---|---|
| **단위** | 훅 스크립트를 직접 부르고 stdin에 JSON을 넣는다 | 종료 코드와 보고 형식 |
| **통합** | `claude -p`로 실제 세션을 열어 도구를 쓰게 한다 | **도구 호출이 실제로 진행되지 않았는가** |

**단위 조건만 두면 「메시지는 냈는데 동작은 진행된 구현」이 통과한다.** 훅 스크립트는 파일을 만들지 않으므로, 스크립트를 직접 불러 놓고 「파일이 생기지 않았다」를 재는 것은 아무것도 재지 않는 것이다.

**통합 조건은 값이 비싸므로 최소로 둔다.** §6.9의 2개이고, 나머지는 전부 단위다.

### 6.1 등록과 배선

- **C1** `payload/claude/settings.json`이 사건 3개에 훅 4개를 선언하고, 선언된 명령 경로 4개가 `payload/` 안에 파일로 존재한다.
- **C2** 훅 스크립트 4개가 `uv` 셔뱅으로 직접 실행되고, stdin의 JSON을 읽어 종료한다.
- **C3** 공용 모듈이 기대 목록에 들어가지 않는다. 배포된 대상에서 등록 확인을 부르면 `ok`가 참이다.
- **C4** `payload/rules.json`의 소유 지점이 `SessionStart` · `PreToolUse` · `PostToolUse` · `permissions.allow` 4개를 덮는다. **훅 배열 3개**에서는 원소 식별자가 `(matcher, command)` 쌍이고 그 쌍이 유일하다. `permissions.allow`는 문자열 배열이라 식별자가 값 자체다.

### 6.2 세션 시작

- **C5** 등록이 온전하면 `session-start.py`가 종료 코드 0으로 끝나고 결손을 보고하지 않는다.
- **C6** 훅 선언 1개를 지운 설정에서 `session-start.py`가 종료 코드 0으로 끝나고, stdout JSON의 `hookSpecificOutput.additionalContext`에 `GRIDFIN_GATE` 줄을 싣는다. 그 줄의 `ok`가 거짓이고 `missing`에 **지운 그 경로가 `hook_declaration`으로** 들어 있다.
- **C7** 선언된 명령 경로가 파일로 존재하지 않으면 같은 형태로 보고하고, `kind`가 `hook_file`이다.
- **C8** 매니페스트가 없으면 같은 형태로 보고하고, `kind`가 `manifest`다.
- **C9** `session-start.py`는 어느 경우에도 종료 코드 2를 내지 않는다.

### 6.3 쓰기 경계

- **C10** 프로젝트 루트 밖 경로로 부르면 `pre-write.py`가 종료 코드 2로 끝나고, stderr에 `GRIDFIN_GATE` 줄을 낸다.
- **C11** 루트 안의 심볼릭 링크가 밖을 가리키는 경우에도 C10과 같이 차단한다.
- **C12** 등록이 온전하고 매니페스트가 있는 상태에서, 루트 안 경로는 종료 코드 0으로 통과한다.
- **C13** 훅 등록이 불완전한 설정에서 `pre-write.py`가 루트 안 경로에 대해서도 종료 코드 2로 차단한다.
- **C14** 매니페스트가 없으면 `pre-write.py`가 루트 안 경로에 대해서도 종료 코드 2로 차단한다.
- **C15** stdin이 JSON이 아니면 종료 코드 2로 차단한다.
- **C16** 사용자가 더한 훅 선언(기대 목록에 없는 경로)이 있어도 등록 확인이 통과한다.
- **C17** 선언이 `${CLAUDE_PROJECT_DIR}` 접두 · `$CLAUDE_PROJECT_DIR` 접두 · 절대 경로 세 형태 중 어느 것이어도 기대 목록과 대조된다.

### 6.4 커밋 경계

- **C18** 선언 설정 파일이 없는 상태에서 커밋 명령을 주면 `pre-commit.py`가 종료 코드 2로 끝나고 **stderr에 `GRIDFIN_GATE` 줄을 낸다.**
- **C19** 선언 설정 파일이 있으면 커밋 명령이 종료 코드 0으로 통과한다.
- **C20** 커밋이 아닌 `Bash` 호출은 선언 설정 파일이 없어도 종료 코드 0으로 통과한다.
- **C21** 인식이 형태 4개를 뚫는다 — 인용 · 환경변수 접두 · 복합 명령 · `-C` 경로 지정.
- **C22** 커밋과 이름이 비슷한 명령을 커밋으로 오인하지 않는다.
- **C23** 훅 등록이 불완전하거나 매니페스트가 없으면, 선언 설정 파일이 있어도 커밋 명령을 종료 코드 2로 차단하고 **stderr에 `GRIDFIN_GATE` 줄을 낸다.**
- **C24** stdin이 JSON이 아니면 종료 코드 2로 차단한다.

### 6.5 포맷

- **C25** `format.py`가 어느 경우에도 종료 코드 2를 내지 않는다.
- **C26** 선언된 포맷 명령이 파일을 고쳤으면 stdout JSON의 `hookSpecificOutput.additionalContext`에 `GRIDFIN_FORMAT` 줄을 싣고, `changed`에 그 파일의 경로가 들어 있다.
- **C27** 선언 설정 파일이 없거나 포맷 선언이 없으면 stdout에 아무것도 쓰지 않고 종료 코드 0으로 끝난다.
- **C28** 선언된 포맷 명령이 파일을 고치지 않았으면 stdout에 아무것도 쓰지 않는다.

### 6.6 워크트리 주입

- **C29** 워크트리에 매니페스트의 항목이 파일로 들어가고, 매니페스트 자신도 함께 들어간다.
- **C30** 주입한 항목이 그 워크트리의 `git status --porcelain`에 뜨지 않는다.
- **C31** 주입한 항목이 무시되는 것은 **배포가 심은 블록**이 한다. 그 패턴이 루트 기준으로 고정돼 하위 경로의 같은 이름을 잡지 않는다. **주입은 무시 목록을 쓰지 않는다.**
- **C32** 이미 추적되는 항목은 건너뛰고, 그 파일의 내용이 바뀌지 않는다.
- **C33** 워크트리의 `.git`이 파일인 상태에서 동작한다.
- **C34** 디렉터리 심볼릭 링크를 만들지 않는다.
- **C35** 대상이 워크트리가 아니거나 매니페스트가 없으면 아무것도 쓰지 않고 종료 코드 2로 끝난다. **워크트리 판정은 `--git-dir`와 `--git-common-dir`의 차이로 한다.**
- **C36** 두 번 실행해도 결과가 같고 **무시 목록 파일이 바뀌지 않는다.**
- **C37** 항목 하나를 복사할 수 없는 상태에서, 나머지를 진행하고 **종료 코드 1**로 끝낸다. 어느 항목이 실패했는지 보고한다. **무시 블록이 주입한 항목을 덮지 않는 경우도 같은 층이다** — 나머지를 진행하고 1로 끝낸다.
- **C38** 주입한 뒤 그 워크트리에서 `pre-write.py`를 단위로 부르면 등록 확인이 통과한다. **막는가는 여기서 재지 않는다** — 통합 층의 조건이고 첫 실행 시점이 M1이다.

### 6.7 갱신 경로

- **C39** 지금 배선(`PreToolUse`에 `(Write, pre-commit.py)` 1개)이 설치된 대상에 재배포하면, 옛 항목이 사라지고 새 항목 2개가 들어간다.
- **C40** 사용자가 더한 `PreToolUse` 항목은 C39에서 살아남는다.
- **C41** 사용자가 더한 `permissions.allow` 항목은 C39에서 살아남는다.

### 6.8 회귀

- **C42** 이슈 #1의 시험이 전부 통과한다. **`payload/` 내용에 결합돼 갱신이 필요한 시험은 갱신하되, 갱신한 시험이 무엇을 재는지는 바뀌지 않는다.** 갱신한 시험의 번호와 이유를 남긴다.

**C42를 조건으로 두는 이유를 적어 둔다.** 이슈 #1의 시험은 픽스처를 실물 `payload/`에서 복제해 만든다(`tests/make-fixtures.sh`). 이 이슈가 `payload/claude/settings.json`의 훅 선언을 2개에서 4개로 바꾸고 `payload/rules.json`에 소유 지점을 더하므로, **몇 개가 갱신을 요구하는지는 구현 전에 셀 수 없다.** 조건은 개수가 아니라 「재는 것이 바뀌지 않는다」에 걸린다.

### 6.9 통합 — 실제로 멈추는가

**단위 조건이 답하지 못하는 것 하나만 여기서 잰다.** `claude -p`로 세션을 열고 도구를 쓰게 한 뒤 결과를 본다.

**결과가 없는 것만으로는 판정하지 않는다.** 모델이 도구를 아예 부르지 않아도 파일은 생기지 않는다. **시도했는데 막혔다**를 재려면 네 가지가 함께 참이어야 한다.

- **C43** 배포된 저장소에서 루트 밖 경로에 쓰라고 시키면, ⓐ 세션 기록에 그 경로의 `Write` 또는 `Edit` 호출이 있고 ⓑ `pre-write.py`가 발화했으며 ⓒ 그 호출의 결과가 차단이고 ⓓ **파일이 생기지 않는다.**
- **C44** 배포된 저장소에서 선언 설정 파일이 없는 상태로 커밋하라고 시키면, ⓐ 세션 기록에 커밋 명령의 `Bash` 호출이 있고 ⓑ `pre-commit.py`가 발화했으며 ⓒ 그 호출의 결과가 차단이고 ⓓ **커밋이 생기지 않는다.**

**ⓐ~ⓒ는 `--output-format stream-json`이 준다.** 그 형식이 도구 호출과 결과, 그리고 훅의 시작과 응답을 실시간으로 흘리는 것이 이미 측정돼 있다(미결 목록 파일의 Q35, 1차 실측 2026-08-12). **ⓑ는 훅이 남기는 부수 효과로도 확인한다** — §3.3의 실측에서 그 방법으로 발화를 확인했다.

**시도 자체를 못 시키면 조건이 성립하지 않는다.** 모델이 지시를 거절하거나 다른 방법을 고르면 ⓐ가 거짓이 되고, 그때는 **통과가 아니라 미판정이다.** 프롬프트를 고쳐 다시 실행한다.

**산출물은 시험 스크립트다.** `tests/verify-hooks-live.sh`를 만들고, 다른 시험과 같은 방법으로 실행되게 한다. **다른 점은 회귀 실행 대상에서 빠진다는 것 하나다** — 값이 비싸고 네트워크를 요구하므로 `tests/verify-hooks.sh`가 부르지 않는다.

**구현 단계에서 최소 1회 실행하고 결과를 커밋 메시지에 남긴다.** 남기지 않으면 「실행했다」와 「만들기만 했다」가 구별되지 않는다.

### 이 검증이 재지 않는 것

1. **훅 등록이 통째로 사라진 경우.** 확인할 주체가 함께 사라진다. 잡히는 것은 일부만 사라진 경우다.
2. **스크립트가 신호를 버리는 경우.** 선언과 파일은 짝이 맞으므로 등록 확인이 통과한다.
3. **대화형 세션에서의 동작.** 실측은 `claude -p`로 했다. Claude Code 2.1.237 · darwin 25.5.0에서 쟀고, 다른 판에서 같은지 재지 않았다.
4. **다른 도구가 사용자 층에 건 훅과 동시 실행되는 영향.** 미결 목록 파일의 Q36이 열려 있다.
5. **검사가 실제로 무엇을 잡는가.** 이 이슈는 경계와 채널만 만든다.
6. **워크트리에서 게이트가 실제로 막는가.** C38이 재는 것은 **주입 뒤 등록 확인이 통과하는가**까지다. 워크트리에서 세션을 열어 실제로 막히는지는 첫 워크트리를 만드는 M1이 첫 실행 시점이다.
7. **`GRIDFIN_GATE`의 내용이 사람에게 쓸모 있는가.** 형식이 맞는지만 잰다.

## 7. 미결

**이 이슈를 막지 않는다.**

- **Q36** — 다른 도구가 사용자 층의 설정에 `PreToolUse`·`PostToolUse` 훅을 함께 걸고 있다. 이 설계의 종료 코드 2 차단과 동시에 실행되는 영향을 재지 않았다. **층이 달라 덮어쓰지는 않는다.** 첫 실행에서 확인한다.
- **Q34ⓑ** — 상태 표시줄에 무엇을 표시할지가 열려 있다. 배포 대상에서 빠져 있으므로 이 이슈에 닿지 않는다.

**미결은 [미결 목록 파일](../../draft/open-questions.md)에서만 관리한다.** 이 절은 해당 항목을 인용할 뿐이다.

## 8. 왜 이것이 먼저인가

**배포가 파일을 옮기고, 훅이 무엇을 막을지 정한다.** 이슈 #1이 경로를 만들었지만 그 경로로 간 것은 자리표시본이다. 지금 grid fin 저장소에 배포하면 게이트가 하나도 서지 않는다.

**선언 설정 파일(이슈 #3)보다 먼저인 이유는 읽을 주체가 없기 때문이다.** 선언 설정 파일은 훅이 읽어서 쓴다. 훅이 없으면 파일만 놓이고 아무도 보지 않는다.

**세션 시작에서 멈추는 게이트를 이슈 #3이 다시 만들지 않게 한다.** 선언된 검사 도구가 설치돼 있지 않으면 세션을 멈춘다는 서술이 [판정 문서](../../draft/judgment.html)에 있는데, §3.3의 실측이 그것을 무효로 만든다. **이 이슈가 먼저 확인 기제를 만들고 차단 지점을 옮겨 두면, 이슈 #3은 같은 실측을 다시 하지 않고 그 기제에 검사 항목만 더한다.**

**그리고 주입 스크립트가 여기 붙는 이유가 있다.** 배포물을 추적하지 않기로 한 순간부터 워크트리에 게이트를 넣는 주체가 필요해졌다. 그 주체가 넣는 것이 바로 이 이슈가 만드는 훅이다. 따로 두면 두 이슈가 같은 목록을 각각 알아야 한다.
