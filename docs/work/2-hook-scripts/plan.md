## 2. 순서와 의존

**순서를 정하는 것은 의존이지 중요도가 아니다.**

```
T1 ─┬─ T2 ─┬─ T3 ─┐
    │      └─ T4 ─┼─ T5 ─── T6 ─── T7 ─── T8
    └─────────────┘
```

| task | 무엇을 기다리나 | 왜 |
|---|---|---|
| T1 | — | 나머지 전부의 바탕이다. 선언이 맞아야 등록 확인이 통과 상태를 가질 수 있다 |
| T2 | T1 | 교차 검사의 대상이 T1이 고친 선언이다 |
| T3 | T2 | 등록 확인을 공용 모듈에서 가져온다 |
| T4 | T2 | 같은 이유 |
| T5 | T1 | 공용 모듈을 쓰지 않는다. 차단하지 않으므로 등록 확인을 부르지 않는다 |
| T6 | T1 | 매니페스트가 새 배선을 담아야 넣을 것이 맞다 |
| T7 | T1 · T6 | `payload/`의 변경 전부가 확정돼야 픽스처가 맞다 |
| T8 | T3 · T4 | 두 경계가 있어야 잰다 |

**T3·T4·T5는 서로를 기다리지 않는다.** 순서대로 하되 하나가 막혀도 다음으로 갈 수 있다.

## 3. task마다 지킬 것

1. **한 번에 task 1개만 잡는다.**
2. **완료 조건이 지금 실제로 실패하는지 먼저 확인한다.** 실패를 확인하지 않은 시험은 없는 시험과 같다.
3. 조건이 이미 통과하면 **시험이 무엇을 재는지 다시 본다.**
4. 끝낼 때 **조건을 하나씩 점검하고 통과·실패의 근거를 남긴다.**
5. **앞 task의 조건이 깨지지 않았는지도 본다.**
6. **교차 검토를 부른다.** 지적은 새 커밋으로 고치고 `amend`하지 않는다.
7. **구현을 일부러 틀리게 고쳐 어느 시험이 잡는지 잰다.** 잡히지 않는 변이가 나오면 시험을 더한다.
8. **시험마다 「실제로 멈췄는가」를 함께 본다.** 출력만 보면 메시지는 냈는데 동작은 진행된 구현이 통과한다.

**T6·T7·T8이 `infra`이므로 시작 전에 조언을 한 번 받는다.** T6은 조건이 12개다.

## 4. 시험을 어떻게 세우나

**훅은 대상 저장소에서 실행되므로 대상이 필요하다.** 시험은 임시 디렉터리에 git 저장소를 만들고 `bin/gridfin deploy`로 실제 배포한 뒤 그 안에서 훅을 부른다. **손으로 만든 픽스처를 쓰지 않는다** — 배포가 실제로 놓는 형태와 어긋나면 시험이 통과해도 실물이 깨진다.

**이슈 #1의 시험이 임시 디렉터리를 정리 범위 밖에 쌓은 적이 있다.** 같은 실수를 하지 않도록 정리를 `trap`으로 건다.

**워크트리 시험이 실행마다 같은 지점을 가리켜 옛 워크트리를 재사용한 적이 있다.** T6의 시험은 실행마다 다른 이름을 쓴다.

## 5. 스펙으로 돌려보낼 것 — 전부 해소됐다

**표로 적는다. 무엇이 걸렸는지와 무엇을 막는지 2열이다.**

| 무엇이 걸렸나 | 무엇을 막나 | 어떻게 닫혔나 |
|---|---|---|
| **공용 모듈의 위치가 정해지지 않았다.** §3.3의 기대 목록이 `.claude/scripts/hooks/` 아래에서 나오므로, 공용 모듈을 그 아래 두면 **확인하는 코드가 자기 자신을 결손으로 잡는다** | T2의 첫 커밋 | **`.claude/scripts/gridfin/gate.py`로 정했다.** 기대 목록을 **「직속 자녀」**로 못 박고, **등록되지 않는 파일을 `hooks/`에 두지 않는다**를 규칙으로 적었다. 위치만 정하면 나중에 `hooks/lib/`를 만들 때 되살아난다 |
| **배포 단위 표에 이 파일이 안 보인다.** [저장 문서 §7-4](../../draft/storage.html#7-4)에 「훅 스크립트 넷」만 있다 | T2 | **표에 행을 더했다.** 등록 4개는 그대로다 — 같은 표가 「등록 4개는 훅만 센다」고 이미 적어 두었고 공용 모듈은 훅이 아니다 |
| **§3.7의 서술이 「훅 스크립트」로만 되어 있다.** 주입이 공용 모듈도 넣어야 한다 | T6. 막지는 않으나 서술이 틀린 채로 남는다 | **서술을 고쳤다.** `files`에 공용 모듈이 들어 있으므로 목록을 순회하면 함께 간다 |
| **`uv` 셔뱅 스크립트가 옆 모듈을 부르는 방법이 없다** | 막지 않는다. 구현 방법이지 계약이 아니다 | **`__file__` 기준으로 `sys.path`에 더하면 동작한다**(1차 실측 2026-08-20, 실행 디렉터리와 무관) |

**앞의 셋은 한 뿌리였다** — 공용 모듈을 둘지 말지를 스펙이 정하지 않았다. **정하고 재발행했다.** 미결 목록 파일의 S34로 남겼다.

**`payload/rules.json`에는 더하지 않기로 했다.** 처음에는 T1에 「소유 지점을 늘린다」를 적었는데, `gate.py`는 텍스트 파일이라 규칙이 없으면 기본 3-way merge로 떨어진다. **필요 없는 계약을 늘리지 않는다.** T1의 범위는 `PostToolUse` 하나를 더하는 것까지다.

## 6. 계획 검토

**따로 회차를 돌리지 않았다.** [작업 절차](../../tmp/work-procedure.md) §1의 6단계 조건이 「5절이 비었거나 걸린 항목이 스펙에 반영됐다」이고, §5가 닫혔다.

**절차서 §11이 「계획 검토를 따로 회차로 돌릴지」를 두 번째 사례를 기다리며 미뤄 두었다. 이슈 #2가 그 두 번째다.** 5절로 대신했고, **5절이 실제로 T2를 막는 항목 셋을 잡았다.** 이슈 #1과 같은 결과다.
